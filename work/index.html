Purgo AI

  • Finding the tables an agent misses

    2026

    Added dbt lineage, which cut missed source tables by about 70% on a benchmark built from real tickets with no ticket losing a table it had already found, and a schema check that drops tables the warehouse doesn’t have.

  • Semantic search over data catalogs

    2026

    Built a semantic search path on Pinecone for Iceberg catalogs on Polaris. It re-indexes only the tables whose schema changed. On 188 ticket-derived queries it found about a quarter more of the right tables than Databricks Vector Search, about 20 times faster.

  • Moving two agent stages to a smaller model

    2026

    Rewrote the retrieval and drafting prompts for a smaller reasoning model and set the reasoning effort for each stage, then switched only after five runs on 102 tickets showed retrieval recall held. The two stages became 7.6 times cheaper, though they’re a small share of a full run’s cost.

  • Self-review for generated code

    2026

    Extended the agent’s review loop with AST lint rules for Databricks runtime errors in generated PySpark and SQL, each traced to a real failure. If every candidate fails, the agent gets one recovery attempt, then keeps the candidate that fails the fewest kinds of checks.

  • The dbt source layer the agent writes against

    2026

    Built the layer that gives the agent the repo’s exact dbt source declarations, plus a review check that rejects generated code that doesn’t match them, so a recurring dbt parse failure is caught at review time.

  • Testing LLMs and Databricks platforms for regulated use

    2025–26

    Built two products for regulated teams, each with its own engine. One qualifies a customer’s LLM (10 behavioral tests, including hallucination, determinism and demographic bias, plus 9 checks on an Azure deployment). The other qualifies a Databricks platform on Azure or AWS (up to 53 tests per cloud, from 59 versioned definitions), and an LLM pipeline turns requirement documents into new platform tests. Reports from both can be signed in the app.

  • Sampling customer tables as agent context

    2025

    Built the service that samples rows from customers’ Databricks tables as context for the agent, with PII and PHI masking (Presidio) that each project can turn on.

Projects

  • ReadableSTEM

    2026

    A free, open-source tool that turns STEM course PDFs into accessible web pages, live as a free beta that anyone can sign in to. On a pre-registered held-out set of 15 OpenStax sections, it got nearly all the headings right and a model judge passed nearly all its figure descriptions. About half its equations came out exactly right from whole pages, and a general chatbot did better there. On a second held-out set, 15 arXiv papers, it scored a little below the chatbots on equations, too close for that set to separate. It also reads scanned and handwritten pages from their image, sending every equation it reads there to review.

    • readablestem.com
    • Source on GitHub

    2026

    The pre-registered, held-out tests against a chatbot and three open parsers, with intervals. Each registered bar is reported as it came out, and the claim that it clearly beats the chatbot on equations was not met.

  • Five fixable causes put ReadableSTEM behind a chatbot on equations

    2026

    Traced its gap to a chatbot to five causes before changing anything, skipped a repair loop the evidence said could catch 1 error in 282, and tested the fixes on fresh papers registered first. The claim I had registered, that it beats the chatbot, was not met.
