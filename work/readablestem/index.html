ReadableSTEM turns STEM PDFs into accessible pages

Upload a STEM course PDF and get back one web page a screen reader can read, equations included. Two models read the maths, the PDF’s own text checks them, and anything uncertain goes to the instructor.

ReadableSTEM is live at readablestem.com, free for anyone with a Google account. The demo needs no sign-in, and the code is on GitHub. How well it works is in the evaluation: the registered tests, why it lost on equations and the chemistry score.

What it does

An instructor uploads a PDF and gets back one web page: equations in MathML, which a screen reader speaks with their structure, real headings and lists, and a short description for each figure. After each conversion it says what changed. This is its summary for the sample document, a 13-page section of OpenStax Physics:

The sample section, as a screen-reader user gets it from the PDF and from the web page
Can a screen-reader userFrom the PDFFrom the web page
hear equations with their structure?The symbols, in a row. In 7 of 17 the fraction bars and subscripts are lost.All 17, as MathML
hear what a figure shows?No. None of the 7 figures has a description.All 7 are described
jump from section to section?No. Nothing marks a heading.36 headings in one outline
hear lists as lists?No. Bullets are read as characters.14 real lists

It assists a person and doesn’t certify a page as accessible.

Result

It got heading levels right for 1.000 of matched headings, against 0.341 and 0.508 for the chatbots, and on papers left fewer wrong equations unflagged: 8.4 per 100, against 13.7 and 16.3. A chatbot still got more equations exactly right, so my registered claim to beat it there was not met.

The evaluation

The problem

A screen reader can read the words in a course PDF but not the maths. In a PDF an equation is glyphs placed on a page: a fraction bar is a drawn line, a subscript is smaller text set lower. The screen reader gets the symbols in a row with the structure gone. Figures rarely have descriptions, and nothing marks the headings.

Universities now have a deadline. Under the Justice Department’s interim final rule of April 20, 2026, state and local governments with a total population of 50,000 or more have until April 26, 2027 to make their web content meet WCAG 2.1 AA, with some exceptions. The rule may still change.

It’s for the instructor who has to fix a course PDF and can’t recheck every equation by hand, and the student who reads the result. So the output has to be right where it’s certain, honest where it isn’t, and cheap enough to offer free.

How it works

ReadableSTEM is one FastAPI service and one Postgres database, which is the job queue, the file store, the spend ledger and the cache of model answers. One database means one deletion path, and the whole thing runs for about $5 to $8 a month before model spend.

A worker claims the oldest queued job with SELECT … FOR UPDATE SKIP LOCKED and a 120-second lease it renews while working. If the process dies, the lease runs out and the job is retried, up to 3 times. Model answers are cached per element, so a retry pays only for what’s missing.

The output is one self-contained HTML file with no scripts, ready for Canvas. Its MathML is rebuilt from an allowlist, never pasted from the model.

Reading the page without a model

The layout comes from the PDF itself, with PyMuPDF and no model call, so it’s free, fast and deterministic, and every later check has something independent to compare against.

Each character is classed by its font and Unicode, and a row that is at least half maths with no prose words becomes a display equation. Fraction bars come from the page’s drawings, since in a PDF they are lines. Tables are found first and taken out, so their numbers are never read as equations.

Two models, and when to escalate

Each element is cropped and read by a vision model: Claude Haiku as the cheap one, Claude Opus as the main one. Short inline equations start on the cheap model and go up when it’s unsure (below 0.85), its output is invalid, or a check against the PDF fails. Each model is the other’s fallback, tried once.

Routing options I compared on the development set
OptionWhat happened
Cheap model first for display equations too27% cheaper per page at the same accuracy, but the cheap model is confident more often, so 7 more of 302 wrong equations reached the page with no question

Cheap first for short inline equations only, escalate on doubtShipped

When the only reason to escalate was a confidence between 0.80 and 0.85, the main model gave the same maths 8 times out of 8, so skipping that band cut 7.1% of the cost.

Checking each answer against the PDF

A model’s confidence said little about whether it was right; the equation model’s confidence ranked its errors worse than chance. So each answer is checked against the PDF’s text layer, which the model never sees, so it can’t copy it.

The check compares the letters, digits and Greek letters in the equation with the PDF’s, then the numbers (36 is not 63), capitals, bold vectors and signs. Any mismatch needs a decision.

The instructor decides

Nothing is published on its own. A change the tool isn’t sure of becomes a decision for the instructor, and everything else is accepted and listed. A scanned or handwritten page can’t be checked, so everything read from its image goes to review.

Questions are the price, so they have to count. Only problems that change what a student reads are required; that cut required decisions on 43 pages from 65 to 10. On held-out textbooks it asks 1.76 questions a page.

Spend capped before it happens

Sign-up is open and I pay the model bill, so the limit has to hold under concurrency, retries and bugs. Every call reserves its worst-case cost before it’s sent, then settles at its real cost.

A daily cap ($10) is one row per day, updated with a conditional UPDATE, so concurrent calls can’t overshoot it; jobs and pages have their own caps, and the provider’s limit sits behind all of them. A job that hits a cap still assembles the page, with the unconverted parts flagged. A typical page costs about $0.0044 to $0.014.

Treating every input as untrusted

Every upload is first opened in a child process with a 30-second limit and a 768 MB memory cap, so a crash or hang kills the child, not the server. Of 837 malformed test files, 41 crashed the parser, and all were stopped there.

PDF text reaches the model only as fenced data, the model has no tools, and everything it returns is validated, so a prompt injection can at worst produce a wrong equation for review.

How far it scales

One instance converts about 1.5 seconds a page on 1 vCPU. At the $10 daily cap, money runs out before compute: roughly 670 dense pages a day. At real scale the worker moves out of the web process into its own service, and since the queue already lives in Postgres, nothing else changes.
