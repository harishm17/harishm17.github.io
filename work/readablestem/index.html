ReadableSTEM turns STEM PDFs into accessible pages

Upload a STEM course PDF or LaTeX source and get back one web page a screen reader can read, equations included. The PDF’s own text checks what the models read, and anything uncertain goes to the instructor.

ReadableSTEM is live at readablestem.com (opens in a new tab), free for anyone with a Google account. The demo (opens in a new tab) needs no sign-in, and the code (opens in a new tab) is on GitHub. How well it works is in the evaluation, from tests I registered before running them.

What it does

An instructor uploads a PDF, or a LaTeX file or a zip of a LaTeX project, and gets back one web page: equations in MathML, which a screen reader speaks with their structure, real headings and lists, tables rebuilt as tables, and a short description for each figure. Scanned and handwritten pages are read from their image when the instructor asks. After each conversion it says what changed. The page downloads as HTML, as a Canvas page or Common Cartridge, as Word or as EPUB. This is its summary for the sample document, a 13-page section of OpenStax Physics:

The sample section, as a screen-reader user gets it from the PDF and from the web page
Can a screen-reader userFrom the PDFFrom the web page
hear equations with their structure?The symbols, in a row. In 7 of 17 the fraction bars and subscripts are lost.All 17, as MathML
hear what a figure shows?No. None of the 7 figures has a description.All 7 are described
jump from section to section?No. Nothing marks a heading.29 headings in one outline, with a skip link and a contents list
hear lists as lists?No. Bullets are read as characters.14 real lists

It assists a person and doesn’t certify a page as accessible.

Result

On 26 documents and 1,715 equations, registered before it ran, ReadableSTEM got 0.840 of equations right end to end, level with the Opus chatbot (0.836); the set can detect no difference. It left 5.0 wrong equations per 100 without a question to the instructor, against 9.6 for the Opus chatbot, and 11.0 per 100 wrong or missing without a question, against 16.4. It cost $0.022 a page on those documents, against $0.068.

The evaluation

The problem

A screen reader can read the words in a course PDF but not the maths. In a PDF an equation is glyphs placed on a page: a fraction bar is a drawn line, a subscript is smaller text set lower. The screen reader gets the symbols in a row with the structure gone. Figures rarely have descriptions, and nothing marks the headings.

Under the Justice Department’s interim final rule of April 20, 2026 (opens in a new tab), state and local governments with a total population of 50,000 or more have until April 26, 2027 to make their web content meet WCAG 2.1 AA, with some exceptions. The rule may still change.

It’s for the instructor who has to fix a course PDF and can’t recheck every equation by hand, and the student who reads the result. So the output has to be right where it’s certain, honest where it isn’t, and cheap enough to offer free.

How it works

ReadableSTEM is one FastAPI service and one Postgres database, which is the job queue, the file store, the spend ledger and the cache of model answers. One database means one deletion path, and the service runs on Railway for about $5 to $8 a month before model spend.

A worker claims a queued job with SELECT … FOR UPDATE SKIP LOCKED and a 120-second lease it renews while working. Jobs with the fewest attempts go first, then the one whose owner was served longest ago, then the oldest, so one person’s ten documents don’t keep another person’s single one waiting. If the process dies, the lease runs out and the job is retried, up to 3 times. Model answers are cached per element, so a retry pays only for what’s missing.

The output is one self-contained HTML file with no scripts, with a skip link, a contents list, page markers and linked footnotes. Canvas, Common Cartridge, Word and EPUB files are made from it, so there is one document to review and check. Its MathML is rebuilt from an allowlist, never pasted from the model. LaTeX source is the one exception, explained below.

Reading the page without a model

The layout comes from the PDF itself, with PyMuPDF and no model call, so it’s free, fast and deterministic, and every later check has something independent to compare against.

Each character is classed by its font and Unicode, and a row that is at least half maths with no prose words becomes a display equation. Fraction bars come from the page’s drawings, since in a PDF they are lines. Tables are found first, taken out so their numbers are never read as equations, and rebuilt as real tables; a cell that is one formula becomes an equation of its own. Headings start from the PDF’s bookmarks when it has them. A PDF made by TeX is recognised from its producer, which turns on rules that need the glyphs: an inline formula starts and ends where its glyphs say, and the unit after a number stays outside it. Each slide of a slide deck becomes a section.

Two models, and when to escalate

Each element is cropped and read by a vision model: Claude Haiku as the cheap one, Claude Opus as the main one. Short inline equations start on the cheap model and go up when it’s unsure (below 0.85), its output is invalid, or a check against the PDF fails. Each model is the other’s fallback, tried once.

Routing options I compared on the development set
OptionWhat happened
Cheap model first for display equations too27% cheaper per page at the same accuracy, but the cheap model is confident more often, so 7 more of 302 wrong equations reached the page with no question
A mid-size model as the main model45% cheaper, but 39 decisions for the instructor instead of 21, and weaker figure descriptions
Cheap first for short inline equations only, escalate on doubtShipped

When the only reason to escalate was a confidence between 0.80 and 0.85, the main model gave the same maths 8 times out of 8, so skipping that band cut 7.1% of the cost.

The text layer cuts an inline formula out of its sentence, and that cut is often wrong at a radical, an integral sign or a stacked fraction. So the model also sees the whole line with the cut boxed, and writes the formula the box is part of. On a registered test this raised exact equations by 2.6 points (interval +1.7 to +3.6) with silent errors not rising, which met the rule I had set for turning it on.

Checking each answer against the PDF

A model’s confidence said little about whether it was right; the equation model’s confidence ranked its errors worse than chance. So each answer is checked against the PDF’s text layer, which the model never sees, so it can’t copy it.

The check compares the letters, digits and Greek letters in the equation with the PDF’s, then the numbers (36 is not 63), capitals, bold vectors and signs. Any mismatch needs a decision. Three later layers use more of the PDF:

  • Glyph checks read the letter styles from the fonts (italic against upright, bold against bold italic, script, double-struck) and notice a reading that runs past its box. Chemistry gets a species check on coefficients, charges, states and arrows.
  • Glyph reconcile corrects a reading from the glyphs only where they leave one answer, such as a named lookalike symbol in a TeX-made PDF. The correction is an optional note and the model’s reading is kept, so the instructor can see both.
  • A flag policy adds a decision for an accepted equation that looks like the readings that turned out wrong. It is a small logistic model with 22 features and fixed constants, fitted on development documents only, with no model call at run time, and it can only add decisions.

Most wrong readings differ from the text layer in nothing the checks can see, which is why the flag policy exists. With these features it did not reach the flag recall I had registered, as the evaluation reports.

The instructor decides

Nothing is published on its own. A change the tool isn’t sure of becomes a decision for the instructor, and everything else is accepted and listed. Each question costs the instructor time, so only problems that change what a student reads are required. On the first textbook run that cut required decisions on 43 pages from 65 to 10. With the flag policy on, the latest test set asks 2.87 questions a page, a price I accepted for fewer silent errors.

The review screen shows the page beside the decision, with both readings where there are two, a list view, and one action that accepts every equation whose checks passed. “Listen as a student” plays roughly what a screen reader would say for the page. An owner can share a finished document with named people to view or to review. One access check covers every route, and each decision a reviewer makes is recorded under their name.

Scans, handwriting, tables and chemistry

A scanned or handwritten page has no text to check against, so it is converted only when the instructor asks, and everything read from its image goes to review. Handwriting limits accuracy whatever the prompt, and the model’s confidence barely separated right equations from wrong ones, so I stopped trying to raise accuracy and made the errors visible. Pen strokes in a vector PDF give one more check: the page’s ink is compared with what was read.

Tables are rebuilt as real tables, and a table on a scanned page is a decision. Chemistry is read as MathML shaped so a speech engine pronounces it, with the species check above. Charts and diagrams also get a long description, and charts with readable values a data table, under rules that stop it inventing a value. I haven’t measured the long descriptions yet.

LaTeX source, in a sandbox

An instructor who writes in LaTeX already has the exact equations. Compiling to a PDF and reading them back from the picture throws that away and then guesses them again. So a .tex file or a zip of a project goes to LaTeXML, which expands the macros as the author’s TeX would and writes the document with MathML. That becomes the same document model a PDF becomes, so review and every export are the ones a PDF job has.

The cost is that a .tex file is a program. It can read files, start programs and loop for ever, and the web service holds the model keys in its environment. So LaTeXML runs only inside a sandbox: a read-only root with no application, no network, an empty environment, and limits on memory, CPU time, file size and wall-clock time. The sandbox is bubblewrap, or Landlock with a seccomp filter where bubblewrap cannot start, which is the case on Railway. If it cannot start, the job fails with “upload the PDF instead” and nothing runs outside it. A start-up probe has to print PASS on the deployed image before the feature may be on, and on November 4, 2026 it did.

LaTeXML’s own MathML, after the same allowlist sanitiser, is the exception to “never pasted”: it is compiled from the author’s source, not guessed from a picture. I considered a separate service with no secrets and haven’t built it. The registered results are all for the PDF path, and I have no measured result yet for source jobs.

Spend capped before it happens

Sign-up is open and I pay the model bill, so the limit has to hold under concurrency, retries and bugs. Every call reserves its worst-case cost before it’s sent, then settles at its real cost.

A daily cap ($10) is one row per day, updated with a conditional UPDATE, so concurrent calls can’t overshoot it. A new account’s documents may use only $4 of it, so strangers can’t take the instructors’ whole budget. Jobs ($6) and pages have their own caps, stored bytes are capped per person, and the provider’s own limit is the last backstop. A job that hits a cap still assembles the page, with the unconverted parts flagged. A new account gets 150 pages a day, and a page cost $0.022 on the 26 documents of the newest test set.

Treating every input as untrusted

Every upload is first opened in a child process with a 30-second limit and a 768 MB memory cap, so a crash or hang kills the child, not the server. Of 837 malformed test files, 41 crashed the parser, and all were stopped there.

A file can pass that probe and still hang or exhaust memory later, so the whole conversion also runs in a child process the worker can kill, with a 3,072 MB address cap, a CPU limit and the job’s wall-clock limit. The child holds no model keys and no database address. Model requests, spend reservations and writes stay in the web process, so the accounting is the same.

PDF text reaches the model only as fenced data, the model has no tools, and everything it returns is validated, so a prompt injection can at worst produce a wrong equation for review. Redirects take their job from the row the ownership check returned, never from the request.

A damaged or hostile PDFRefused at upload with a sentence naming the problem; no quota spent

How far it scales

In a benchmark with simulated model latency, a 12-page document took 19 seconds with 8 steps at a time, about 1.6 seconds a page. At the $10 daily cap and $0.022 a page, money runs out first, at about 450 pages a day. At real scale the worker moves out of the web process into its own service, and since the queue already lives in Postgres and is already fair between people, nothing else changes.

Next is the equation work that the registered claim still needs: silent errors under 4.0 and a higher flag recall. Chemistry is below its bar of 0.80 right. The second figure set has a pre-registration that I haven’t signed, so the long descriptions stay unmeasured. The screen-reader test has a written protocol and no results, the accessibility conformance report is a draft, and the Canvas export hasn’t been tried in a real Canvas.
