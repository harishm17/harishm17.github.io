Work at Purgo AI, 2025–present

Designing retrieval and code review for a data-engineering agent

I work on Purgo AI’s data-engineering agent, a multi-agent LangGraph system that turns a data team’s ticket into PySpark, SQL and dbt code. My work covers the whole agent: retrieval, context engineering, prompts, orchestration and evals. I measure each change on real tickets.

I designed the agent’s retrieval: the pipeline that picks the few tables the LLM sees out of hundreds. Its hard case is a table the ticket needs but never mentions. Search ranks it low, the reranker drops it, and the agent writes code against the wrong table. My fix parses the SQL of the dbt models the ticket does mention, follows their lineage upstream and keeps those tables in context however the reranker scores them. I chose the design by ablation: four variants on about a hundred real tickets.

I also set the context budget across tables, attachments and repo code, moved two stages to a smaller, cheaper model with no loss in recall, and built several of the review loop’s checks and the recovery path for when every draft fails.

Testing LLMs and Databricks platforms for regulated use

I built both products end to end. Life-sciences companies use them to validate an AI model or a Databricks platform before regulated work.

One tests an LLM for hallucination, consistency across repeated runs, demographic bias and latency under load, against thresholds the customer sets, with a separate judge model for free text.

The other runs versioned test definitions against the customer’s own Azure or AWS workspace, and an LLM pipeline drafts new tests from a requirements document for a reviewer to approve. Each run ends in an evidence report the customer signs for its auditors.
